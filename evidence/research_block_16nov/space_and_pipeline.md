The inference boundary does **not** require any incumbent member, posterior mean, SessionEM, TSEM, route, feature space or classifier. A complete alternative can output class labels directly, use its own causal state, or learn its own session stage. The current system remains a useful measured comparison, not the definition of a valid method.

**Fixed model versus labelled inference context:** public-labelled data may train a model offline, and fixed learned parameters may be shipped. The FAQ does not explicitly classify a TabICL key/value cache compiled from labelled public examples as fixed model parameters. Immutable precomputation avoids fitting on source rows during `predict`, but does not by itself settle whether a labelled example cache is permitted. Do not treat test-time fitting, gradient adaptation on labelled source rows, or an unclarified labelled-context design as authorized by the FAQ. Offline distillation into ordinary fixed weights avoids this specific ambiguity.

## Signal and representation path

- `scripts/export_windows.py:32–65` uses the official NeuralBench extraction and saves all three public splits, each window, class, person, session, task, interface, run and onset. Public metadata is an analysis and training resource, not a hidden model input. Its optional offset overrides generate alternative public training crops; the default provides one official task window per cue.
- The native recording has 41 EEG channels; no **separate** EOG/EMG input is provided. Frontal and edge EEG can still contain eye and muscle activity. It is wrong to equate the absence of auxiliary channels with absence of ocular or muscular signal. The finite 120 Hz signal cannot preserve arbitrary 500 Hz high-frequency content. The 50/60 Hz notches and anti-alias resampling limit it further; precise retained spectrum and edge behavior need direct extractor inspection, not inference from the label alone.
- `lean/src66/tangent.py:27–52` subtracts the across-channel mean (common-average reference, CAR), computes filtered covariance blocks, updates an unconditional prefix log-covariance reference, and separately appends a slowly filtered waveform. `lean/src66/inputs.py:57–69` applies unconditional prefix covariance whitening to aligned network inputs. `experiments/session_bn.py:47–85` also mixes current-prefix latent means and variances with training priors. These are choices, not organizer constraints.
- CAR removes the instantaneous common-mode component. It can reduce shared reference contamination, but can also discard common-mode task signal. Band covariance explicitly subtracts each channel's within-window mean; the separate slow block can retain low-frequency shape. A 0.1 Hz high-pass does not prove the finite-window mean is zero. §282's simple mean-over-time logistic model reaches 46.06% person-equal on these public windows; that is descriptive predictive signal, not proof of a neural source or a general solution. Its 52.65% REVE mid-layer result also uses noncausal whole-session z-scoring (`studies/15nov/kit282/kit282.py:34–42`), so it is an offline probe rather than a streaming package result.
- Current `sosfiltfilt` calls process a complete already-delivered window, e.g. `experiments/features.py:16–25`; this is compatible with the stated stream contract. Filtering whole future windows, using their labels or using an entire test-session reference is not a deployable causal evaluation. The organizer's fixed preprocessing occurs before streaming; its documented filtering is not a license for our session adapter to peek ahead.
- In the [NeuralSet v0.4.0 extractor](https://github.com/facebookresearch/neuroai/blob/v0.4.0/neuralset-repo/neuralset/extractors/neuro.py), filtering and resampling operate on continuous raw recordings before segmentation. The local v0.4.0 files hash-identically to upstream, and local MNE 1.13.2 `create_filter(None, 500, 0.1, 75)` returns a 16,501-tap FIR (33 s total, ±16.5 s support). Thus this local preprocessing can mix samples from outside the nominal crop; that is fixed preprocessing, not permission to read future delivered windows. It does not establish usable adjacent-trial label information, actual leakage, or the precise hidden-worker MNE configuration. Segment boundaries and filter-padding behavior also matter. Within-session train/test splits may share temporal input support despite non-overlapping nominal crops; leave-one-person-out keeps the entire person apart. Do not infer that this overlap materially changed any existing result without a controlled test.
- `scripts/export_external.py:70–86` explicitly uses spherical-spline interpolation for missing **external-corpus** electrodes. Interpolated channels do not create independent measurements. §277 deliberately discarded external interpolated coordinates to obtain a 26-channel common intersection. §282's ledger calls PROTEUS itself “spline-interpolated”, but its script loads `protocol.load()` from the ordinary PROTEUS export. The [v0.4.0 PROTEUS loader](https://github.com/facebookresearch/neuroai/blob/v0.4.0/neuralfetch-repo/neuralfetch/studies/dreyer2026proteus.py) reads the EDF and says it does no cleaning; the inspected NeuralSet raw preprocessing path has no interpolation call. This evidence does not support claiming the standard PROTEUS export uses the external spline mapping; it does not rule out prior processing before the public EDFs were published.
- The 14 Nov neuroscience panel (`evidence/review_14nov/panel_neuroscience.md:3–34`) reports exploratory, unscripted—not preregistered or chain-tested—signals: ocular features 0.47 LOSO versus 0.66 within-session, spectral 0.50 versus 0.70, with substantial person differences. Its 40–58 Hz edge-channel proxy achieved 0.37 LOSO / 0.44 within. Those limited probes do not establish that ocular or muscular information, clean cortical activity, or the WORD class is exhausted. They do indicate that interpreting these signals as purely neural is unsupported.
- §222 directly contradicts a stronger “all class information is below 8 Hz” inference from variance shares: among its single-band probes 8–13 Hz performed best for the population member (44.8% new) and true-label template probe (66.6% new). The 1–4 / 4–8 Hz probes and their specific reduced views were weaker. These are individual estimators and views, not an exhaustive test of multi-band fusion or frequency-specific architectures.
- The raw-data inventory `evidence/levers_14nov/m2_raw_inventory.txt:6–41` records 1,288 non-overlapping public rest windows and up to nine overlapping four-second crops per task trial. Overlapping crops are not independent trials and all crops from a held-out person must stay out of that fold. `studies/14nov/ssl/ssl_form2.py:13–31` actually used five task offsets plus external windows, **no rest loader**; `mk_crops.py:1–8` lists four additional offsets rather than the preregistered full 0.5 s grid. Thus §277 form 2's negative result does not test rest-augmented SSL. `studies/11nov/rest4/rest4.py:1–6,45–52` does train a fourth class from **pre-cue Graz task-run windows**; that is not the separate eyes-open/eyes-closed baseline data.

## Important implementation confound: §98 synthetic rotations

`studies/12nov/sys3.py:24–29` claims its QR matrix is a small rotation: `Q = np.linalg.qr(I + 0.15/sqrt(d)*noise)[0]`, checked only by `mean(abs(diag(Q))) > 0.8`. Git blame attributes that formula and guard to `36b4384`, the ledger's stated pre-result fix. QR factorization permits column sign flips. The saved `runs/sys3_inputs.npz` has 737 features. A read-only numerical reproduction at `d=737`, seed 0, exact noise scale yielded 736 negative and one positive diagonal, mean **signed** diagonal −0.9861, but mean **absolute** diagonal 0.9888; the code's guard passes. Training uses `X @ Q`, while evaluation uses `X` (`sys3.py:37–45`). Therefore a near-global sign reversal is a concrete possible train/test distribution mismatch. The Leonardo job's copied source and original-run traces were not inspected, so the original execution and the cause of its below-chance result remain unverified. If it used the documented code, its result is not a clean test of the intended *small-rotation* task. Separately, the episode keeps recording order and the transformer has explicit position, so this was not training against the current shuffled-delivery protocol. No fix or rerun was made.

## Questions to size next, not approved runs

1. For class-mix contamination, compare label-balanced versus unbalanced **prefix** reference geometry with labels used only as an offline oracle; quantify class-specific alignment and cell-balanced downstream losses, across pinned permutations and held-out people. An oracle result is a ceiling for that defined diagnostic, not a deployable model. If there is headroom, specify a label-free update and test it as a whole alternative, with the new representation propagated to its own stages.
2. For adaptation-aware initialization, choose a small model and an actual deployable, label-free inner update. Train across public training people using separate prefix/support and later query windows, never held-out-person labels; compare ordinary training, joint auxiliary training, and post-update-objective training with matched compute, seeds, runtime and full-system checks. Avoid selecting on query labels in the deployed inner loop.
3. For input and artifact contributions, retain a native-reference/common-mode view, a CAR view and an ocular-separated view as distinct hypotheses. Evaluate them by held-out person and session and by interface cell; report standalone performance and a jointly rebuilt stage, not only fixed-weight posterior fusion. Test sensitivity to cropping/filter boundaries and offsets without mistaking interpolation, overlap, or rest windows for independent participants.
4. For honest generalization, retain an additional external session/corpus instrument where the class/task mapping is valid; never use an external test person for its own training or tuning. Give person-nested uncertainty, both P04/P10 separately, and the unknown hidden-cohort mixture. Do not infer hidden data or scores from public oracles.

## Adversarial priority check

| Proposal | Reason to pursue | Best counterargument and decisive check |
|---|---|---|
| Class-aware SPD centering | Targets a specific upstream failure that posterior rebalance cannot undo. Start with the true-label prefix diagnostic, then pre-register a strictly causal label-free alternative as a whole system. | Our hidden label proportions are unknown; strongly forcing balanced predictions can itself misalign imbalanced prefixes. §104's pseudo-class rotation failed badly. Measure error by prefix and order, compare no-op/standard centering, and quantify cost. OSPDIM's published task was binary MI; source-only statistics and any access to source examples must respect the evaluation rule. |
| Meta-trained causal adaptation | Explicitly optimizes performance **after** the actual label-free update rather than assuming joint auxiliary training makes gradients useful. §246 shows a privileged-label reference; §255/256 give negative controls for several separate auxiliary-loss designs. | Nine training people per held-out fold are weak meta-training support; pseudo-label errors can dominate and reuse of the same sessions biases selection. Distinct person-disjoint outer validation, support/query separation in delivery order, matched ordinary/joint training and a no-update test are mandatory. Compute and final-system feasibility remain unmeasured. |
| DEFT whole model | [DEFT](https://arxiv.org/html/2610.14497) explicitly separates task-content and subject-style tokens and reports subject-disjoint gains, including arithmetic; training identities are not inference metadata. Compare a matched pretrained backbone and an equal-capacity generic adapter. | The results are not PROTEUS or the current full system; four seconds gives few temporal tokens, channel averaging may discard useful topographic asymmetry, and subject information can help returning-person recognition. On one task the paper's style and content probes retained similar subject identity. Existing CBraMod fine-tuning was weak; DEFT is untested, its code rights and A100 cost are unresolved. Treat new-person and returning paths separately and test the whole decoder without requiring the old stages. |
| Low-cost tabular whole classifier | Public window features, compact covariance projections, or frozen embeddings could support a fast nonlinear classifier; scikit-learn is present in the worker. The ledger has linear and small neural whole systems but no verified direct tree-family whole-system result found in this search. | Limited people, 44k correlated core columns, per-session centering and model selection can make simple nonlinear fits overfit badly. Compare against logistic regression on **the exact same fold-fitted compact features**, with a held-out-person inner selection; evaluate class-balanced cells over multiple delivery orders as a complete classifier, including its own state if any. Do not infer full-pipeline gains from isolated feature probes. A fixed labelled TabICL context has the unresolved rule question above; use a distilled fixed model if clarification is unavailable. |

Priority is conditional on a concrete registered comparison, provenance and compute budget. Small cheap diagnostics rank first for decision value; none of the four has a measured v6.6 full-system improvement. Short-deadline ranking cannot be justified from published cross-dataset gains alone.
