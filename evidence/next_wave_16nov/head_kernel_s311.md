# §311 CPU head-kernel audit, 16 Nov 2026

The completed §301 P01 nine-person benchmark measured full solves of roughly 19.2–19.6 seconds for sklearn and 243.4–244.1 seconds for the original native CPU L-BFGS. Those solvers used different stopping conditions, and the native solve ended at a tighter objective. The comparison did not isolate language, objective-kernel or optimizer effects.

§311 in `docs/LEDGER.md` registers an independent float64 analytical softmax gradient beside the existing native autograd implementation. Both use the same C=.3 mean cross-entropy plus weight-only L2, exact same source matrix and parameters. A separate fit uses the same LibTorch L-BFGS settings as the existing fit, with only the gradient computation changed. Original head APIs and queued §305/§309 snapshots are unchanged.

Build **3115438** precedes real-source mini/full objective and gradient identity smoke **3115439**; paired warm objective timings and matched-settings complete fits **3115440** depend on that smoke. These are sequential, one six-core bound CPU allocation at a time, with no GPU. The smoke requires absolute loss and maximum gradient differences ≤1e-9 and exact P01 source-row exclusion before the benchmark can run. Both stages record source and library hashes. The benchmark also records CPU affinity, thread counts, loaded numerical libraries, full-solve loss/gradient/evaluation counts and RSS. Full-solve times are upper bounds on first reaching the target, not measured time to that target.

All three jobs completed 0:0. On the exact P01 source matrix of 2,465 × 44,239 values, full-matrix loss difference was zero and maximum gradient difference was 2.18e-17; the first-32-row gradient difference was 2.83e-16. A separate native call rejected a NaN input. Six logical CPUs were bound, comprising three sibling pairs. Across three paired warm calls, the full checked objective-and-gradient API took 0.3062–0.3111 s with autograd and 0.2793–0.2865 s analytically. The fixed-call API checks input finiteness on every call; the optimizer validates input once, so those call timings cannot simply be multiplied by optimizer evaluations.

One same-settings complete L-BFGS pair took 41.44 s and 370 objective evaluations with autograd, versus 37.61 s and 433 evaluations analytically. Final objectives differed by 1.40e-11, with maximum gradients about 3.4e-7. Both reached the registered common target, but the measurements do not record when they first reached it. These are one paired fit on one machine, not a broad language comparison; changing CPU threading or hardware also prevents direct causal comparison with the earlier §301 solve times. The source matrix was borrowed without a per-call input copy; output allocation, numerical validation and resulting copies were included. Sampled process peak RSS was 2,571,244 KiB. The report records Torch/OpenMP and NumPy OpenBLAS libraries and thread counts. No held accuracy was read.

Reports are `runs/s311_smoke/report.json` and `runs/s311_bench/report.json` in the immutable workspace. The new kernel remains an engineering experiment; no package, worker or energy claim follows from it.
