# Track 2 research · Refit timing and delayed recognition

17 November 2026. Primary-source and implementation review ran 20:22:43–20:37:45 CET (15m02s). This note compares the frozen cap250 decoder with two proposed causal control changes. It uses the recorded campaign context and exposed development cohorts.

## Decision

Read §362's paired upper bound first for the higher-ceiling question. If the two complete branches fix different errors, estimate whether signed correction value transfers on honest source folds. The §321 adapter retains the original net bank, gates and FT for both recipes. A worker could compute those once and maintain separate outer-tail, count-filter and CP histories, plus the six added networks. This requires exact two-branch replay and a measured cost on the existing worker budget. Keep the current frozen artifact as the comparison. [Full-branch ceiling study](branch_ceiling362.md) · [Actual JS adapter](../../studies/17nov/js_readiness321/adapter.py)

For a shorter independent experiment, test whether the incumbent improves when it spends fixed adaptation work on more informative prefixes. Start with the CPU causal personalization (CP) refit clock. Its output is terminal, its input banks have a package-identity check, and its refit and decision costs can be measured separately. Neural fine-tuning (FT) changes later predictions throughout the outer chain. Its policy needs separate, complete trajectories per arm. The refit study has a modest accuracy prior and can run with the frozen implementation.

Treat delayed identity commitment as contingency work. The frozen package turns a transient positive gate into a session-long decision about FT and CP. Genuine late sessions and natural false accepts decide whether this matters. Historical rates imply a small average effect from eliminating rare false accepts alone.

## Experiment A · Allocate CP refits by additional class support

The current package refits eight-band CSP/LDA every 20 windows from index 20. It selects the confident half within each pseudo-class. Its first positive emission weight is at index 90. A change to the refit clock affects the maintained models but leaves the supplied EEG and upstream outputs intact. This differs from §361, which holds the clock fixed and changes the fitted covariance estimator. [CausalPers implementation](../../submissions/lean_v66/submission.py#L1272) · [Reference replay and package guard](../../studies/14nov/newmember/s281_cp.py)

- **Arm proposal.** Run stock, fixed cadence 40, and one adaptive cadence. All attempt the original initial refit at 20. At every later stock opportunity, the adaptive arm obtains the original classwise selected-row set from past proposals. Require two pseudo-classes. Refit when there is no successful fit yet, a new class has at least three selected rows, or each class in the last successful fit has gained two newly selected row IDs. Keep the stock one-window entry point, output ramp, training-row selection, covariance estimator and LDA. The refit also needs enough budget.
- **Cost comparator.** The sparse arms can refit through index 250. Charge `t` prefix-window work units at a refit on index `t`. Credit only the costs of fixed cadence 40 appointments already due, at indices 20, 60, 100, 140, 180 and 220. The adaptive arm therefore spends at most what fixed cadence 40 would have spent for any realized session length. This is a deterministic work bound. Actual machine cost requires timing. Log selected-row counts, classes, per-fit time, feature preparation and whole replay time. Compare score and physical cost jointly. A candidate that computes the discarded refit to select its action has no saving from skipping that fit.
- **Authentic inputs.** Predeclare one actual source-only stream for path and cost smoke, then run all six dependent bases and eight pinned orders on the original complete `all_loso` control banks. The hand rule above uses no fitted parameters or task labels. Check matching fold, input, package and permutation hashes. Returning comparisons use real session-1 enrollment and separately held sessions 2–3. CP is terminal. The verified stock stop before 90 proves structural identity for this scheduling change in the 32 §321 proxy streams. A later recognized stream requires its own full paired replay. §321's retained priors keep any reused returning score conditional. [Existing stop-position proof](fractional_csp361_proof_summary.json)
- **Causal checks.** Reproduce every stock final label and original score within `1e-8`. In stock-policy mode, the *same* scheduling hook must keep all original refit action indices. The older count-filter helper loads archival `y` at import for a row guard. Use a metadata-only input path for the new producer and keep that label guard and `replay/check.py` in the collector after complete proofs. Check that no refit uses its current row, that changing future rows leaves a shared prefix exact, and that reset and interleaved sessions keep independent states. Require at least one differing refit and a changed posterior while the CP weight is active. Each arm builds its own CP state. [Legacy input guard](../../studies/14nov/rundetect/package.py#L22)
- **Numeric prior and refutation.** Adaptive minus fixed cadence 40 **+0.15 pp** [80% prior −0.35,+0.70]. Adaptive minus stock **+0.10 pp** [−0.45,+0.55]. Both are new-person whole-decoder changes. A negative 80% upper bound against the direct control refutes that comparison. A positive comparison at a higher measured cost leaves the timing-at-cost hypothesis untested. If paired predicted labels never differ despite active refits, the refit scheduling has no measurable decision effect on this cohort. Small or crossing-zero effects remain undecided. Report official equal-cell and people/order estimates, P04/P10 effects, J and the 57/43 sensitivity proxy where genuine returning rows permit them.
- **Feasibility.** Start with one CPU2/8 GiB/8-minute no-score smoke. The adjacent §361 two-arm CPU replay completed in 1,037 seconds with exact archived controls and no established gain from its covariance modification. Its 32 conditional returning streams stopped CP by index 63, before fusion at 90. Remeasure this recipe before authorizing at most one full CPU2/8 GiB/45-minute replay. Its refit schedule and control bank cardinality differ from §361. [§361 timing and guard](fractional_csp361.md)

**FT extension only with measured headroom.** Keep the same deterministic refit work accounting but include full-prefix forward, backward and StreamBN rebuild cost. The historical A100 378/800-window cap250 stress paths took 78.15/155.00 seconds with 24 FT refits and ~14 seconds recorded for refits after the first. Those pairs changed CP and cap together, so they cannot isolate a savings estimate for FT. A paired one-event pilot would hold versus do the index-40 refit, keep later stock opportunities, and compare all final labels through the horizon. Copy the exact weights, StreamBN, RNG, FT inputs and outer state before branching. Feed the same causal EEG and reconstruct the downstream tail, count filter and CP for each actual path. A clean FT schedule arm cannot take a prefix or replay checkpoint from a different action history. [Frozen timing log](../v66_15nov/t66c-3105586.out) · [FT implementation](../../submissions/lean_v66/submission.py#L1029) · [Current native worker timing scope](native_worker360.md)

There is also a separate score-preserving performance hypothesis. Stock CP fits from scratch at 20, 40, 60 and 80, then emits its first personalized decision at 90. On a successful session, the refit at 80 overwrites all older models and uses the same stored covariances and posteriors. Suppressing the earlier fits could save time with identical labels on that path. Earlier refit failures can change the stage's lifetime, so an exact optimization would have to preserve that behavior or show where it changes. Test it separately from adaptive cadence. [CausalPers implementation](../../submissions/lean_v66/submission.py#L1309)

Train a small cost-sensitive selector only if offline source rollouts show consistent gains over the same-work fixed schedule. For each training example use the labeled *source* difference between alternate completed trajectories. Its feature vector may use only information available before the action. If using LOSO outputs to fit a selector, require nested decoder banks excluding both the held person and the source person supplying that training example. Archived ordinary LOSO predictions for another person may have used the outer person's labels. A look-ahead gain over greedy is a reason to test sequential reinforcement learning. A saved prediction matrix from one policy cannot evaluate a persistent action under another. ## Experiment B · Separate proposed routing from ending adaptation

The frozen `Route` picks the larger ramp on each window and gives contrast the tie. The first positive ramp separately sets an irrevocable session flag `recB`. In cap250 this rewrites the stored FT labels, stops executing FT and clears CP state for the rest of the session. Later loss of the ramp does not clear `recB`. The same split is explicit in native `Runtime`. Hold every per-window candidate and ramp fixed. Change only when the decoder commits to stopping adaptation. [Frozen route and latch](../../submissions/lean_v66/submission.py#L827) · [Frozen FT/CP consumption](../../submissions/lean_v66/submission.py#L1515) · [Native runtime](../../native/src/runtime.cpp#L97)

- **One fixed form.** Keep per-window routing candidates and ramps unchanged. Require the same winning identity with a positive ramp on three consecutive delivered windows before stopping FT and CP. A changed or absent winner resets the counter. The stock baseline ends adaptation on the first positive ramp. A one-hit policy through the same hook must reproduce the original scores, route and counters. Any extra FT can change the outer tail and count filter after recognition. Replay the complete stream to capture that effect. The historical repeated-hit biometric audit did not change the FT/CP decision path.
- **Pairing.** Enroll each genuine returning participant only from session 1. Replay both later sessions for P04 and P10 under all eight orders, with exactly the same fit assets and current source exclusions in each pair. Require natural positive events with no pending-candidate identity information from future rows. Report any actual held-session exposure in retained priors as conditional, and never fit this rule on the later-session command labels. For new people, verify LOSO exclusion and simulate no forced identity event in the primary cohort. For an engineering falsification canary, use actual EEG and supply a prospective one-step positive ramp through a gate fixture on exactly one past index. This is a state-transition check and must not enter measured cohort accuracy.
- **Existing opportunities.** Among the 32 conditional returning stream/order instances, stock first recognizes six times at 60, once at 20 and once at 59. With an unbroken three-hit confirmation, those eight instances would each newly cross a scheduled FT appointment before commitment. This is a static consequence of the checked stop indices and the 20/10 FT schedule. The new weights and final decisions still require actual paired replay. [Recognition positions](fractional_csp361_proof_summary.json) · [Active frozen FT schedule](../../docs/V6_BUILD.md)
- **Quantify complementarity.** At each natural delayed event, record the number of restored CP/FT windows, exact stock-versus-alternative winners and correction/destruction counts using the official cell score. Within a three-label cell, a correct change contributes `1 / (C × 3 × n_cell,class)`. If a true class is absent, report complete-cell score deltas since predicted classes can change the denominator. A per-window oracle may size decision headroom only between two complete, legal trajectories after outputs are frozen. Never use gold to drive a replayed decoder state. A classifier's own error probability alone does not tell whether the other trajectory is correct. [Official metric source](https://github.com/neural-interfaces26/2026-competition/blob/main/benchmark_utils/metrics.py) · [Learning to defer](https://proceedings.mlr.press/v119/mozannar20b.html)
- **Prior/stop.** Return-weighted mean **0.00 pp** [80% prior −0.35,+0.35]. Predict no changed labels in the all-LOSO orders whose gates never cross. Report both returning people separately, disagreement counts and recognition timing. An upper interval below zero refutes the exact delay form. Before scheduling quality, inspect existing label-blind gate trajectories for any delayed event that reaches an FT opportunity or active CP fusion. If all still commit before those changes, report the available cohort cannot probe the proposed mechanism. Verify that separately on a source smoke and stop the accuracy wave for that cohort.
- **Cost.** The existing §350 CPU replay used about 333 seconds for its complete P04 two-session pilot. Use one source two-stream smoke capped at 15 minutes on two CPUs. Consider a 16-cell CPU2/20-minute each maximum only if meaningful natural events exist and the paired smoke supports it. An unchanged returning output must follow from path activity or a verified complete output pair. Validate reset, an interleaving, common inner-gate traces, and the first and last active adaptation increments before opening gold. Reuse stock outputs only after source, device, order and exact-hook identity checks. [§350 actual pilot and costs](policy350_results.md)

With the historical 1.9% external false-accept estimate, .57 new-person weighting and −2.2 pp mean wrong-route harm from v5.1, eliminating that old mean penalty would recover about **0.024 pp** in that scenario. The estimate omits new lifecycle effects and uses a different decoder. It prioritizes a focused audit over a new threshold search. At the optimistic §266 +4.8 proxy difference, recovering all of a 13% missed-returning share would correspond to about **.27 pp** under the .43 returning proxy. That same-session advantage and external miss rate do not estimate sealed transfer. ## Limits from primary research and the rules

- Yoo et al. trigger updates with measured shift/change in object-detection streams. This supports trying a cheap trigger. Their chronological drift and reference distributions differ from the challenge's shuffled prefixes. Niu et al. select low-entropy, nonredundant samples for image-model updates. This evidence pertains to training-sample selection, while Experiment A changes when the downstream refit happens. [Yoo et al.](https://openaccess.thecvf.com/content/CVPR2024/html/Yoo_What_How_and_When_Should_Object_Detectors_Update_in_Continually_CVPR_2024_paper.html) · [EATA](https://proceedings.mlr.press/v162/niu22a.html)
- Schirmer et al. monitor test-time risk without target labels using a false-alarm condition relating a proxy and true error. They report that verifying the premise still requires labels. A confidence or entropy monitor here is a hypothesis whose signed ability to predict incremental gains must be checked on held people. [Monitoring Risks in Test-Time Adaptation](https://proceedings.neurips.cc/paper_files/paper/2025/file/746960ad49ddb47248970a0e1404230c-Paper-Conference.pdf)
- Alfarra et al. simulate fixed-rate streams that can miss adaptation opportunities when an update is slow. Track 2 supplies one delivered window per call and requests one answer for each. The relevant resource claim is paired end-to-end time under the 60-minute A100 rule, including worst credible unrecognized paths and setup. Native §360 still failed the long actively adapting exact-label guard. Use the qualified frozen dev reference to test quality until the worker port qualifies. [Time-constrained evaluation paper](https://proceedings.mlr.press/v235/alfarra24a.html) · [Binding rules](https://neural-interfaces26.github.io/rules.html) · [Current scientific FAQ](https://raw.githubusercontent.com/neural-interfaces26/2026-competition/main/codabench/pages/scientific_faq_bci.md) · [§360 record](../../docs/LEDGER.md)
