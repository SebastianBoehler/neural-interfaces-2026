# What a reproducibility audit needs on the training side (list only; nothing here is built)

The organisers rerun the training pipeline of the top three teams. `lean/` covers inference: one source tree, a
deterministic bundle, a builder that copies data files, and a window-by-window comparison of two packages. The
data files of `cand_v51b_own` (`weights.npz`, `teacher.pt`, 30 `sbn_*.pt`) come from a chain of about ten build steps
spread over `scripts/`, `experiments/` and `studies/12nov/`. The audit would additionally need:

1. **One recipe from raw data to the package.** `docs/AUDIT_NXIF.md` and `docs/AUDIT_SBN.md` document the chain up
   to `cand_rec_ts2_tsem_route3geb_fast` (v3). The two last steps have builders and checkers but no recipe with
   reference values: the identity gate (`scripts/add_bio_gate.py`, v4.1) and the own-space stage
   (`scripts/add_own_stage.py`, v5.1b). A single entry point should run all steps in order and end in
   `lean/tools/build.py`.
2. **The identity gate's external model.** It is fitted by `experiments/bio_id.py` on external multi-session
   corpora (default list: Lee2019_MI, Stieger2021, Yang2025, Kumar2024, GuttmannFlury2025_MI, Zhou2020; 224 people
   per `docs/STATE.md`). Needed: the export script and checksums of those windows, the fit command that produced
   `bio_model_psd_d64.npz`, how the threshold 0.26 was chosen, and each corpus's licence. These corpora are not
   in the licence table of `docs/AUDIT_NXIF.md`.
3. **A cluster-neutral pipeline.** The existing recipes are Slurm job chains for the Tübingen ML Cloud (account,
   partitions, `sbatch` wrappers in `scripts/cloud/`). The organisers need plain commands with the compute each
   step takes (the recipes give about 8 GPU-hours for the teacher trunks and SincShallowNet initialisations;
   the SessionBN families, cores, routing, gate and own-space steps need the same accounting).
4. **Frozen code for every step.** Builders import study code (`scripts/add_own_stage.py` imports
   `studies/12nov/ownspace.py`), and recipes for some intermediate packages point to an older commit (`c4d600d`).
   Each step needs one commit at which it runs, and the builders must take the bundled `submission.py` instead of
   copying `submissions/ensemble_v5*/submission.py`.
5. **Seeds and what a rerun can reproduce.** The nets are trained on GPUs and are not bit-reproducible;
   `docs/SEALED_UPLOADS.md` already notes that a rebuild does not reproduce the weights' digest. Needed: every seed
   (member seeds 0–5 per SessionBN family, teacher seeds 0–11, pretraining seeds 0–4, scikit-learn solvers), the
   steps that are deterministic on CPU (cores, TSEM and routing PCs, galleries, heads, own-space models) with
   their expected digests, and for the trained nets a measured spread of the score across retrainings, since the
   audit rule is a rescore within ±2σ of the submitted score.
6. **Pinned environment and hardware.** `requirements/cloud.txt` (torch 2.14.1+cu126, braindecode 1.8.1, MNE
   1.13.2, MOABB 1.7.2, numpy 2.5.4, scikit-learn 1.9.1, neuroai 0.4.0, exca 0.5.29), the lock file a prepare run
   writes, the GPU types used per step, and the official submodule revision.
7. **Data provenance with checksums.** The official PROTEUS release and the exported windows
   (`scripts/export_windows.py` → `data/proteus_windows.npz`), the seven motor-imagery corpora of the teacher
   (`scripts/sealed_nxif_inputs.sha256`), and the identity gate's corpora (item 2). Scherer 2015 was cleared by
   the organisers on 11 Nov; state whether any shipped array depends on it.
8. **Intermediate artefacts that are not in git.** Pretrained trunks (`runs/pretrain/`), SessionBN checkpoints
   (`runs/sbn/`), the identity model, and `runs/replay_data/`: each either regenerated by the recipe or archived
   with a digest.
9. **Provenance of every constant.** Member weights, `rb_alpha` 1.15, the SessionEM / TSEM / early-boost
   constants, the gate thresholds (0.22, 0.26), `route_slot_g` 3 and `own_beta` 0.10 were chosen on public data;
   the ledger sections that record each choice should be listed next to the key, together with the fact that
   candidate selection also saw five sealed scores.
10. **Declarations for the method description.** All ten public participants are used for training, and their
    sessions also give the per-person galleries, personal heads and own-space models; the external corpora and
    licences; the cue-order regularity noted in `docs/STATE.md` §2.
11. **An acceptance test on outputs, not bytes.** A retrained package cannot match bit for bit. The comparison
    should be `lean/tools/record.py` + `parity.py` between the shipped and the rebuilt package (label agreement and
    posterior differences per case), plus the official replay score. The tolerance has to be measured (item 5),
    not assumed.
12. **Worker-image replay.** The CPU parity shown here does not prove behaviour on the Linux/A100 worker; the
    worker image is on Galvani. One replay of the lean package there is still owed before any upload.
